# Vortex FOMOD C# host

Real Windows/.NET implementation of the `--request` contract used by the core
node helper for FOMOD archives containing `fomod/script.cs`.

The host references the same installer assemblies as `installer_fomod_ipc` and
runs the FOMOD engine directly; it does not open a UI. C# execution is gated by
`allowCSharpScripts` in the request, which the C++ core only sets after explicit
consent.

## Build

Windows x64 with .NET 9 SDK:

```powershell
$dist = pnpm -F @vortex/main exec node -p "require('path').dirname(require.resolve('@nexusmods/fomod-installer-ipc/package.json')) + '/dist'"
dotnet build native/fomod-host/VortexFomodHost.csproj -c Release -p:FomodInstallerDir="$dist"
```

The output is `bin/Release/net9.0-windows/VortexFomodHost.exe` together with the
installer assemblies. `prepare-dist-package.mjs` stages it under
`resources/native/fomod-host` and the main process picks it up automatically on
Windows, or from `VORTEX_FOMOD_CSHARP_HOST`.

## Verification

- `tests/FomodDynamicTest.csproj` validates the dynamic delegate contract and
  runs on Linux and Windows.
- `.github/workflows/fomod-host-windows.yml` builds the host and executes a
  scripted FOMOD that calls `GenerateDataFile`, asserting the generated bytes.
